### `workflow/schemas.py` (Pydantic models)

Field names and shapes match the proposal **Schema and key interfaces** table. Use `pydantic` `BaseModel` (and appropriate types). `Ballot` does not include a total field; totals are computed in code later. `CostEstimate` is not defined in this step (Step 3, `workflow/cost.py`).

| Model | Fields |
| --- | --- |
| `ResearchIdea` | `title`, `question`, `claim`, `population`, `outcome`, `why_it_might_be_nonobvious` |
| `Comment` | `objection`, `alternative` |
| `MethodPlan` | `design`, `data`, `comparison`, `main_threat` |
| `Critique` | `fatal` (`bool`), `flaws` (`list[str]`), `required_change` |
| `RevisedProposal` | `idea` (`ResearchIdea`), `method` (`MethodPlan`), `what_changed` |
| `CriterionScore` | `round_index` (`int`), `non_obvious` (`int`, 1 to 5), `feasible` (`int`, 1 to 5), `method_fits_question` (`int`, 1 to 5) |
| `Ballot` | `voter`, `scores` (list of five `CriterionScore`) |
| `TurnRecord` | `role`, `kind`, `iteration`, `payload`, `input_tokens`, `output_tokens`, `reasoning_tokens`, `latency_ms` |
| `RoundRecord` | `round_index`, `seed_role`, `thread_id`, `brief_sha256`, `turns` |
| `VoteRecord` | `thread_id`, `ballots`, `ranking`, `top_three` |
| `StudyResult` | `run_id`, `model_id`, `reasoning_effort`, `brief_sha256`, `rounds`, `vote`, `total_input_tokens`, `total_output_tokens` |

`TurnRecord.payload` is `dict[str, object]`, the `model_dump()` of the turn's Pydantic response. Imports must stay valid without calling a model.

### `workflow/roles.py`

- **`RoleSpec`:** `role_id`, `display_name`, `system_prompt` (per proposal table).
- **`ROLE_ORDER`:** tuple of exactly five `RoleSpec` instances in seed order from proposal **Who speaks**. Use these `role_id` values, in this order:
  1. `social_psychologist` for the social psychologist working on computational social science
  2. `computer_scientist` for the computer scientist working on measurement from digital traces
  3. `communications_researcher` for the communications researcher working on online discourse
  4. `sociologist` for the sociologist working on networks and inequality
  5. `political_scientist` for the political scientist working on political behavior
- **Staff roles (not in `ROLE_ORDER`):** three additional `RoleSpec` values, with these `role_id` values:
  - `synthesizer` restates the discussion only
  - `methodologist` writes and revises the design only
  - `critic` names flaws only
- Every system prompt must include the three rules from proposal **Who speaks**: stay in the assigned job; return only the schema; if a prior study is mentioned, say it was not checked and do not invent a citation.
